# DMS UX review — October 27, 2026

Scope: authenticated local synthetic DMS, not the proprietary marketing site. Reviewed 25 screens at 1440/390/320px: Home; vehicle list/detail/create/edit; customer list/detail/create; deal list/create/desk/review/files/history/trade; follow-ups; account list/detail/payment/receipt/schedules/illustration/export; feedback entry/list. Sign-in also inspected. This is a developer review, not a full accessibility audit or staff usability study.

## Findings and design plan

The sampled screens had no outer-page overflow or visibly unlabeled inputs. Existing task-first record views are substantially clearer. Biggest remaining friction is data entry and secondary navigation:

- At 390px, Save vehicle begins at y=2572, Save customer y=868, Save deal y=971. Primary actions need to remain reachable during entry.
- Vehicle costs/notes are secondary but occupy the same always-open hierarchy as identity/title/mileage.
- Checkbox text and controls use separate vertical rows. Make the label/control one clickable group.
- Follow-ups has no selected main section and lacks a direct return destination.
- Sign-in uses an abstract slogan instead of naming the task.
- Generic form errors inside disclosures need the same reveal-and-focus behavior already used in the deal desk.

Reuse Manrope and brand green #204c41, ink #1c2c27, white #ffffff, paper #f7f9f7, border #dbe3dc, amber #fff4d8. Layout: bounded readable entry panels, sticky in-flow save/cancel row, ordinary required-field indicators, optional costs/notes disclosure, explicit breadcrumbs. Keep title and mileage facts visible and unknown defaults unchanged.

```
Add vehicle
[identity / title / mileage]
> Costs and notes
[Save vehicle] [Cancel]     <- reachable while scrolling
```

Review: avoid turning forms into a wizard or adding decorative metrics. Preserve existing entered values, warnings, server validation, duplicate review, private upload controls and financial gates. Sticky actions must not obscure focused fields; test phone layout and keyboard focus. Checkbox labels must keep generated IDs, help/error associations and escaping. New disclosure must open on its errors. No financial methods, data schema, monetization or production behavior changes are proposed.

## Deferred observations

Schedule illustration entry exposes inputs for both calculation methods. A later focused pass should clarify method-specific entry while preserving values, error visibility and explicit financial assumptions. Do not silently erase inactive values or alter calculations during a visual cleanup. Feedback privacy explanations are long but consequential and remain visible.

## Changes completed

- Vehicle/customer/deal entry now uses readable bounded panels and a sticky Save/Cancel row. At 390px / 900px height, the button begins around y=832–835 instead of y=2572/868/971 respectively. The bar remains in the form; no duplicate financial submit actions were added.
- Vehicle costs/notes starts collapsed and opens for its own server errors. Identity, title and mileage remain visible. Values/defaults are retained, including required zero cost inputs.
- Shared field rendering joins checkbox controls with their clickable text, retains labels/help/error IDs and shows a small Required indicator for required non-checkbox inputs. The payment form reuses that renderer.
- Generic entry forms reveal disclosure ancestors for invalid fields and error-summary links. Focused controls scroll clear of the sticky action bar, with label/field scroll margins and root scroll padding. Browser checks caught and corrected an initial label interception by the bar.
- Follow-ups selects Deals in the main navigation, has a direct breadcrumb and actionable empty-state links.
- Sign-in uses a direct task heading and plain Sign in action. Customer validation summary now links to individual field errors.

## Verification and limits

Full PostgreSQL suite: **332 tests passed**, 112.781 seconds. Browser before/after scans: 25 authenticated screens at 1440, 390 and 320px, plus sign-in inspection. No sampled outer-page overflow or visible unlabeled inputs. Main navigation is selected on Follow-ups after the fix; feedback intentionally uses the user menu rather than an unrelated main tab.

Interaction checks passed: label-click checkbox toggling; native invalid hidden cost opens and receives focus; server-rejected negative cost retains entered work and opens the disclosure; error link focuses the cost field without the action bar obscuring it; follow-up return destination. Only an invalid synthetic vehicle form was posted, not a saved vehicle or financial posting. Screenshots inspected for entry/record views. Ignored evidence: `.local/ux-audit/` contains before/after JSON, screenshots, interaction results and test log.

This does not establish complete accessibility conformance, actual staff usability validation, financial review or production readiness. No public push or production deployment occurred.
